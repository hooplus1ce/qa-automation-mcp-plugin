# 通用 UI 自动化测试执行提示词模板

> 使用说明：
> - 本文件是**按需读取**的提示词模板，未注册为 Skill，AI 不会自动加载进上下文。
> - 用法：让 AI 读取本文件，并给出下列占位符的实际值，即可开始执行。
> - 一个场景一个文件（如 `vtable-数据校验-template.md`），互不干扰。

---

```markdown
# 通用 UI 自动化测试执行任务

## 一、任务定义
对 {测试用例文档}（路径或附件）中的子表/工作表：{子表名}，按 {过滤字段} 过滤出
等于 {过滤值} 的全部测试用例，逐条调用 qa-automation 插件的能力执行 UI 自动化测试。

## 二、执行前置
1. 被测系统：{被测系统 URL}；测试账号：{账号}（若未登录，先用 click_interact /
   fill_input 完成登录）
2. Chrome 以 --remote-debugging-port=9222 启动（插件经 CDP 接管本地 Chrome）
3. 用例文档列映射：{用例编号 / 用例名称 / 前置条件 / 测试步骤 / 测试数据 / 预期结果}

## 三、测试结果判定（逐条，互斥）
- 通过：页面数据信息与流程符合"测试步骤 + 测试数据 + 预期结果"
- 不通过：出现至少 1 点与预期结果不符
- 待定：用例自身信息（步骤/数据/字段）与页面实际不符，或环境问题导致无法
  完成验证、无法判定对错
回填规则：测试结果（下拉：通过/不通过/待定）；执行人={执行人}；执行时间=当前
系统时间；备注（通过：留空；不通过：简要失败原因；待定：说明哪一步骤/哪个
数据/哪个字段与页面不符）。

## 四、执行方式（动作链优先）
每条用例按"分析 → 执行 → 验证 → 留证"四步：
1. analyze_current_page 分析页面结构与可用定位器
2. execute_action_chain 批量执行步骤（click/fill/select_option，依赖动作级
   fallbacks 容错）
3. wait_for_condition 验证关键反馈（成功提示/元素出现），必要时
   probe_dynamic_layers 复核浮层；VTable 表格场景用 vtable_* 工具读取数据断言
4. 关键节点 capture_screenshot 留证，filename 统一
   "{二级模块}/{用例ID}_{步骤}.png"（工具自动创建子目录）
失败处理：动作失败先读返回的错误（定位超时/元素不存在/严格模式多匹配），用
probe / wait_for_condition 复核页面实况，不盲目重试同一动作。

## 五、证据资产保存（每测完一条立即执行）
1. JSON 证据：{证据根目录=项目根 evidence_assets}/{二级模块}/{二级模块}.json
   - 不存在则创建；存在则先读取、合并、再整体写回（追加，绝不覆盖）
   - 每条记录字段：用例编号 / 用例名称 / 二级模块 / 测试步骤 / 测试数据 /
     预期结果 / 测试结果 / 执行人 / 执行时间 / 备注 / 截图路径列表 / 失败详情
2. 截图：测试结果为"不通过 / 待定"时必须 capture_screenshot 留证（含页面
   状态与关键元素），路径写入该记录的"截图路径"字段；"通过"不强制。

## 六、测试报告（全部用例测完后）
基于上述 JSON 生成 Markdown 报告，保存至 {报告路径=output_testcases/
{二级模块}_测试报告.md}：
- 汇总表：用例编号 / 名称 / 结果 / 执行人 / 执行时间 / 备注
- 统计：通过 / 不通过 / 待定数量与通过率
- 重点章节：不通过、待定用例逐一给出失败原因、截图、现场描述
- 文档末尾：每个不通过 / 待定用例按 {Bug 系统=禅道} 提交规范给出模板
  （标题 / 优先级 / 所属模块 / 前置条件 / 重现步骤 / 实际结果 / 预期结果 /
   附件截图 / 环境信息）

## 七、汇报节奏
每自动化测试完一条用例，立即汇报该条执行情况（用例编号 / 名称 / 结果 /
关键证据路径），等待我确认后再执行下一条。
```

## 占位符速查

| 占位符 | 含义 | 示例 |
|---|---|---|
| {测试用例文档} | 用例文档路径/名称/附件 | 生和堂APS项目测试用例V2.0(普通表) |
| {子表名} | 用例文档中的工作表/子表 | 基础配置 |
| {过滤字段} / {过滤值} | 用例筛选条件 | 二级模块 / 数据字典 |
| {被测系统 URL} / {账号} | 待测系统入口与登录账号 | 按实际填写 |
| {执行人} | 回填的执行人 | Hoo |
| {证据根目录} | JSON/截图保存根目录（相对用户项目根） | evidence_assets |
| {报告路径} | Markdown 报告输出位置 | output_testcases/{二级模块}_测试报告.md |
| {Bug 系统} | Bug 提交模板格式 | 禅道 / Jira / 飞书 |
